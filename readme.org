** reload/visit this emacs configuration
Convenience function to visit and reload our emacs configuration files.
#+begin_src elisp
(use-package emacs
  :init
  (defun config-visit()
    "Visit the emacs config directory, to quickly access and make changes."
    (interactive)
    (find-file user-emacs-directory))
  (defun config-reload()
    "Reload the user config, to get the latest saved changes"
    (interactive)
    (load user-init-file))

  :bind
  ("C-c e" . 'config-visit)
  ("C-c r" . 'config-reload))

* Default behaviors
** Backup files
Set emacs backup and auto-save folder to =~/<emacs-dir>/backups=, so
they do not create file artifacts next to our files, but deactivate
the automatic creation of lock files.
#+begin_src elisp
(use-package emacs
  :custom
  (backup-directory-alist `(("." . ,(concat user-emacs-directory "backups"))))

  ;; auto-save files go in the same folder, which has to exist
  (auto-save-file-name-transforms
   `((".*" ,(concat user-emacs-directory "backups/") t)))

  ;; do not create/use lockfiles (used to prevent collisions, breaks react)
  (create-lockfiles nil)
  :init
  (make-directory (concat user-emacs-directory "backups") t))
#+end_src

** Isolate autogenerated emacs =init.el= to =custom.el=
Emacs stores some configuration in a file, which by default is the
=./init.el= file. This makes vendoring the init.el in Git tricky, so we
can change it to its own file, and load it (otherwise we would not
load our changes through =M-x= =customize=).
#+begin_src elisp
(use-package emacs
  :init
  (setq custom-file (concat user-emacs-directory "custom.el"))
  (when (file-exists-p custom-file)
    (load-file custom-file)))
#+end_src

* package manager
To use emacs packages, we first need to require its built-in
package management functionalities.

We can also define additional package archives, where the remote
packages can be downloaded from.
#+begin_src elisp
(use-package package
  :custom
  (package-enable-at-startup nil)
  (package-archives
   '(("melpa"        . "https://melpa.org/packages/")
     ("gnu"          . "https://elpa.gnu.org/packages/")))
  ;; Only download remote packages: built-in ones (like `treesit`) are
  ;; not known to package.el, so a global `:ensure t` makes use-package
  ;; refresh the archives and fail to install them on every startup.
  ;; Packages from an archive must declare `:ensure t`; `:vc` ones install
  ;; themselves.
  (use-package-always-ensure nil))
#+end_src

*** pinentry
Some docs on these settings is found on [[https://stackoverflow.com/questions/60812866/emacs-gpg-pinentry-el-for-authentication][Stackoverflow1]] and
[[https://emacs.stackexchange.com/questions/70460/tramp-ssh-connection-inside-eshell-with-gpg-key][Stackoverflow2]].

Pinentry should load after =exwm=, so windows system is loaded before.

#+begin_src elisp
(use-package pinentry
  :ensure t

  :custom
  (epg-pinentry-mode 'loopback)

  :config
  (require 'epa-file)
  (epa-file-enable)
  (pinentry-start)

  ;; Uncertain if there are any side effects.
  ;; somehow fixes .org.gpg files saving, that was hanging
  (fset 'epg-wait-for-status 'ignore)

  (require 'org-crypt)
  (org-crypt-use-before-save-magic)

  ;; Set GPG public key for encrypting `*.org.gpg` files
  ;; Find yours with: gpg --list-keys --keyid-format LONG
  (let ((key "0DE5CBA2A8FE5321880ED070D784362D37DCAB00"))
    (setq epa-file-encrypt-to key)
    (setq org-crypt-key key)))
#+end_src

Be sure that the =pinentry-*= program are well installed, and that
emacs is "requesting the correct one" (=pinentry-gtk-2= is sometimes
default, and gtk2 might be missing).

In =~/.gnupg/gpg-agent.conf= we can add:
#+begin_quote
enable-ssh-support
allow-emacs-pinentry
allow-loopback-pinentry
pinentry-program /usr/bin/pinentry-emacs
#+end_quote

Don't forget to add the keygrip of the GPG managed SSH (authentication,
=[A]= key) to the file =~/.gnupg/sshcontrol=.

#+begin_src bash
# find the keygrip of secret keys (GPG, SSH managed by gpg)
gpg --list-secret-keys --keyid-format LONG --with-keygrip

# check if the ssh-agent has been fed the key by gpg-agent
ssh-add -l # this should display our key when it works

# check with github if we can connect with our SSH key
# errors as we can't connect with SSH, but should say key is authorized
ssh -v git@github.com
#+end_src

           go-ts-mode rust-ts-mode kotlin-mode
           svelte-ts-mode astro-ts-mode)
          . eglot-ensure))
  :custom
  (eglot-autoshutdown t)
  (eglot-extend-to-xref t)
  (eglot-sync-connect 1)
  (eglot-connect-timeout 60)
  (eglot-report-progress t)
  :config
  (add-to-list 'eglot-server-programs
               ;; ~/bin/kotlin-lsp links to the kotlin-lsp.sh of the latest release

  (add-to-list 'eglot-server-programs
               '(astro-ts-mode . ("astro-ls" "--stdio"

  (add-to-list 'eglot-server-programs
               '(svelte-ts-mode . ("svelteserver" "--stdio")))

  :bind (:map
         eglot-mode-map
         ("C-c c a" . eglot-code-actions)
         ("C-c c o" . eglot-code-actions-organize-imports)
